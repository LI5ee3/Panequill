# Panequill 产品定义

> 状态：v0.1
>
> 本文档定义 Panequill 当前的产品目标、范围与明确不做的事项。涉及“应该做什么”时，以本文档为准。

## 1. 产品定位

Panequill 是一个仅供个人使用的 Web Dashboard / 浏览器起始页。

它通过卡片式 Widget 组织个人常用信息、工具和快捷入口，并在桌面、平板和手机浏览器之间同步个人配置。

Panequill 不面向公众运营，不以多用户、分享、协作、商业化或 SaaS 为目标。

## 2. 核心目标

Panequill 只解决以下问题：

1. 提供一个可以长期使用的个人浏览器起始页。
2. 使用 Widget 组织常用信息、工具和快捷入口。
3. 保存 Widget、布局、快捷入口和界面偏好。
4. 在个人的不同设备之间同步这些配置。
5. 云端暂时不可用时，仍能使用本地已有的 Dashboard。
6. 尽量降低部署、数据库和同步系统的维护成本。

## 3. 产品原则

### 3.1 个人使用优先

所有设计首先服务单个使用者。

不为不存在的公共用户、团队或商业场景提前增加架构复杂度。

### 3.2 本地体验优先

Dashboard 的日常交互不能依赖每一次云端请求。

拖动、调整尺寸、修改 Widget 和其他界面操作应先在浏览器本地立即生效，再异步同步到云端。

### 3.3 云端只负责持久化与跨设备同步

Supabase 不作为 Panequill 正常交互的实时运行依赖。

云端主要承担：

- 身份验证；
- Dashboard 状态持久化；
- 多设备同步。

### 3.4 保持简单

当前需求可以通过简单方案完成时，不拆分出额外服务、权限层、数据库模型或同步协议。

仅在实际需求出现后扩展。

## 4. 产品形态

Panequill 的核心形态是 Web 应用。

不要求浏览器扩展作为主要运行方式。用户可以直接通过浏览器访问 Panequill，并根据浏览器自身能力将其设置为启动页或常用入口。

这样可以同时覆盖桌面、平板和手机浏览器。

## 5. Dashboard

Dashboard 是 Panequill 的主界面，也是当前唯一需要维护的个人工作区。

需要持久化的 Dashboard 状态包括：

- Widget 列表；
- Widget 布局；
- Widget 配置；
- 快捷入口；
- 用户界面偏好。

当前不为多个 Dashboard、团队空间或共享空间设计额外模型。

## 6. Widget

Widget 是 Dashboard 的基本内容单元。

Widget 系统应允许后续逐步增加不同类型的小组件，但当前不预先定义所有未来 Widget 类型。

所有 Widget 遵循相同的基本状态原则：

- 状态可以保存在本地；
- 需要跨设备保存的配置进入统一 Dashboard 状态；
- Widget 不自行实现独立的云同步系统。

## 7. 壁纸

Panequill 的壁纸来源固定为 Microsoft Bing Daily Wallpaper。

当前不考虑：

- 其他在线壁纸提供商；
- 用户上传壁纸；
- 自定义壁纸库；
- 将 Bing 壁纸复制到 Supabase Storage。

壁纸属于外部展示数据，不属于 Dashboard 核心持久化数据。

## 8. 本地数据

Panequill 必须在浏览器本地保存可用的 Dashboard 状态。

本地状态负责：

- 首屏快速恢复；
- 交互后的即时写入；
- 云端请求期间保持界面可用；
- 暂时离线时保留用户当前状态。

具体存储与同步策略由 `ARCHITECTURE.md` 定义。

## 9. 云端同步

Panequill 使用 Supabase Free 作为个人云端同步后端。

云端只保存需要跨设备持久化的个人配置数据。

第一阶段不使用 Supabase Realtime。同步采用普通的读取与写入请求。

## 10. 身份验证

Panequill 使用身份验证保护个人云端数据，但不提供面向公众的注册体系。

身份验证只用于：

- 确认当前使用者身份；
- 防止匿名访问个人 Dashboard 数据；
- 为 Supabase Row Level Security 提供身份依据。

当前不需要用户管理后台、角色系统或权限矩阵。

## 11. 明确不做

以下内容不属于 Panequill 当前产品范围，也不应为了“未来可能需要”而提前实现：

- 公开注册；
- 多租户 SaaS；
- 公共 Dashboard；
- Dashboard 分享；
- 团队协作；
- 管理后台；
- RBAC / 多角色权限系统；
- 社交功能；
- 商业化与订阅计费；
- Supabase Realtime 实时协作；
- WebDAV 主同步系统；
- 多套并行云同步后端；
- 自建 PostgreSQL 与自建账号系统；
- 为公开产品场景预留兼容层。

## 12. 数据可迁移性

Panequill 的核心 Dashboard 状态应保持清晰、结构化和可导出。

即使云端使用 Supabase，也不应把个人配置绑定到无法迁移的内部状态。

导入、导出和备份功能可以在实际需要时增加，但不要求当前同时实现 WebDAV 或第二套同步系统。

## 13. v0.1 成功标准

v0.1 达到以下条件即可视为基础闭环成立：

1. Panequill 可以作为独立网页正常打开。
2. Dashboard 可以展示并管理 Widget。
3. Widget 布局与配置能够可靠保存在浏览器本地。
4. 同一个人的不同设备能够通过 Supabase 同步 Dashboard 状态。
5. 云端短暂不可用时，本地已有 Dashboard 不会因此无法使用。
6. Bing Daily Wallpaper 能够作为唯一壁纸来源正常工作。
7. 不引入与个人使用无关的多用户或 SaaS 复杂度。

## 14. 变更原则

如果后续需求与本文档冲突，应先修改产品定义，再修改实现。

不得因为某个技术方案“未来可能有用”而自行扩大产品范围。
